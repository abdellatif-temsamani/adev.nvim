# Plan: Fix copy/cut/paste edge cases in line-based planner

## Problem

The new line-based planner blindly appends pending copy/move ops with their original `dst` path. If the user renames the pasted line before saving, the destination is stale. The old system re-resolved via extmark IDs (`projection.current_by_id[dst_id]`).

Additionally, if the user deletes the pasted line before saving, the pending op should be cancelled (not executed).

## Solution

Update `planner.plan()` to re-resolve pending copy/move destinations from the current buffer state using extmark lookups.

## Files to modify

### 1. `lua/adev-files/core/planner.lua`

Update `plan()` signature to accept `buf`:
```lua
function M.plan(original_lines, current_entries, root, pending_ops, buf)
```

In the pending ops section, for each copy/move op:
- If `op.dst_id` is set, call `marks.row_for_node(buf, op.dst_id)` to get current row
- Parse the current line at that row to get the current entry
- Use current entry's `abs_path` as the new destination
- If row is nil (line was deleted), skip the op and remove it from pending_ops
- If `op.dst_id` is not set, fall back to `path.abs(op.dst)`

Add `marks` import.

### 2. `lua/adev-files/sync/plan.lua`

Update `plan_ops()` to pass `buf` to `planner.plan()`:
```lua
local ops, plan_err = planner.plan(original_lines, entries, st.root, state.get_pending_ops(buf), buf)
```

### 3. No other changes needed

- `clipboard.lua` — unchanged, still creates pending ops with `dst_id`
- `render.lua` — unchanged, still shows labels from `pending_ops`
- `apply.lua` — unchanged, still applies ops via executor
- `executor.lua` — unchanged, still handles copy/move ops

## Edge cases handled

1. **Paste → save**: Pending op has `dst_id` → lookup row → parse entry → resolve dst → execute copy/move
2. **Paste → rename → save**: Pending op `dst_id` → lookup row → parse renamed entry → resolve new dst → execute with new name
3. **Paste → delete line → save**: Pending op `dst_id` → lookup row → nil (deleted) → skip op, remove from pending
4. **Cut → paste**: Source marked `#del` → planner matches by name (no delete op) → pending move op resolves destination → execute move

## Verification

1. Copy a file, paste, save → file copied to same location
2. Copy a file, paste, rename pasted entry, save → file copied with new name
3. Copy a file, paste, delete pasted line, save → no copy executed
4. Cut a file, paste at cursor, save → file moved to new location
5. Cut a file, paste, rename, save → file moved with new name
6. Copy multiple files, paste, save → all copied
